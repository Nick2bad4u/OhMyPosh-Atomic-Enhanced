# Repository map

## Canonical root sources

- `OhMyPosh-Atomic-Custom-ExperimentalDividers.json`: independent source for ExperimentalDividers prompt structure, dividers, tooltips, integrations, and behavior.
- `OhMyPosh-Atomic-Custom.json`: Atomic Custom family source.
- `1_shell-Enhanced.omp.json`, `slimfat-Enhanced.omp.json`, `atomicBit-Enhanced.omp.json`, and `clean-detailed-Enhanced.omp.json`: independent family sources.
- `color-palette-alternatives.json`: palette definitions consumed by family generators.
- `starship-atomic-enhanced.toml`: separately shipped Starship configuration; it is not an Oh My Posh generation input.

## Generated palette overlays

The folders `atomic/`, `1_shell/`, `slimfat/`, `atomicBit/`, `cleanDetailed/`, and `experimentalDividers/` contain palette-only `extends` overlays. Each overlay must extend its own root family source. The complete Original theme remains at the repository root; family folders must not contain generated `*.Original.json` files.

Use `Generate-AllThemes.ps1` for the five non-ExperimentalDividers families and `Generate-ExperimentalDividers.ps1` for ExperimentalDividers overlays. Never repair broad drift by hand-editing overlay files.

## Generated root helper variants

The root contains complete helper themes generated by `Make-*Variant.ps1`, including Fish, NoShellIntegration, NoNetwork, Extended, ColorCycle, Gradient, GradientRamps, and GradientRampsAutoShade variants. Declarative helper inputs live under `scripts/variants/`.

Atomic Custom also has a generated ColorCycle helper. A canonical ExperimentalDividers change can affect all ExperimentalDividers helpers, so regenerate the full helper set unless the inspected generator contract proves the change is isolated.

## Preview system

- `scripts/Generate-ThemePreviews.ps1` discovers root JSON themes by parsed `blocks` or `extends` structure and includes every generated family overlay.
- `theme-preview.data.json` is sanitized recorded v1 segment data passed through Oh My Posh `--data-only` rendering.
- `image.settings.json` maps repository preview settings to supported Oh My Posh v30 image flags.
- `assets/theme-previews/*.svg` and the README gallery are generated together.
- `scripts/Test-ThemePreviewExport.ps1` smoke-tests representative runtime exports, SVG settings, committed gallery coverage, root-theme coverage, and README-to-asset parity.

Do not restore legacy gallery PNGs or manually tune individual generated SVG files. Adjust the owned settings, fixture, width selection, or generator logic and regenerate.

## Validation and automation

- `scripts/Test-Themes.ps1`: JSON, template, source, overlay, and repository theme invariants; add `-IncludeGenerated` after generation changes.
- `scripts/Pre-Upload-Validation.ps1`: focused upload/readiness checks.
- `scripts/Validate-Palette.ps1`: palette references and theme palette validation.
- `scripts/Test-ThemePreviewExport.ps1`: Oh My Posh v30 SVG preview and committed-gallery contract.
- `.github/workflows/theme-tests.yml`: installs a checksum-verified Oh My Posh binary and runs the broad theme and preview gates.
- `.codex/config.toml`: enables the official Oh My Posh validator MCP for config and segment schema checks.

## Supporting tools

- `scripts/New-ThemeWithPalette.ps1` and `scripts/New-ExperimentalDividersThemeWithPalette.ps1`: create a focused palette overlay; use the family generators for checked-in bulk regeneration.
- `scripts/Inspect-ThemeSegments.ps1`: report segment structure, caches, widths, interactivity, and divider metadata before a behavioral edit.
- `scripts/preview-themes.ps1` and `scripts/Theme-Functions.ps1`: interactive local preview helpers, separate from deterministic gallery export.
- `scripts/Sync-ThemeTemplatesFromAtomicCustom.ps1`: deliberately copies selected shared settings into the four independent non-Atomic base themes. Run only when the task requests that synchronization and review each root-theme diff.
- `scripts/Dev-Generate-All.ps1`: broad development orchestrator that also stages root helper changes. Avoid it when staging is not intended; explicit generators provide clearer ownership.
- `scripts/Sync-Official-Themes.ps1`: mutating Git subtree update for the upstream snapshot. Run only for an explicitly requested sync after checking worktree state and remotes.
- `THEME-GENERATOR-README.md` and `docs/THEME-GENERATION-TOOLS.md`: user-facing generator guidance. Treat the scripts and tests as the executable source of truth if documentation drifts.

Nested `AGENTS.md` files contain the authoritative rules for scripts, generated families, assets, docs, workflows, and the upstream official-theme snapshot.
